The rules that do not bend

  1. One token file. Colour, type, space, radius, shadow, motion and z-index come from tokens.css. A page never types a hex colour; npm run lint:css rejects it.
  2. Colour means a person or a department, not a page type. Steve is green, Ruth is purple, Bradley is slate, the shop floor is blue, the AE dashboard is maroon. Money and quoting is NW green. Two greens and two blues exist on purpose — never merge them.
  3. Reference pages wear the staff chrome, not a person's colour. Training, policies and the handbook use the Training Center's green header (--color-dash-theme) and a neutral tile on the staff dashboard. Customer-facing pages use the brand green (--color-brand).
  4. Printed sheets use the print palette. The fillable forms are printed at the counter; their colours were sampled from the official PDFs and stay exact (--print-*).
  5. A page's own colours are declared once. If a page genuinely needs a colour that is not a token, it goes in ONE :root block at the top of that page's stylesheet — and nowhere else — so re-theming the page is one edit.
  6. No !important except the generated quote-builder-inline.css and a print rule that must beat JS-toggled state, which carries a written reason.
  7. Tokens load first. The token file declares the cascade layers (reset → tokens → base → components → utilities → overrides); a page stylesheet is linked after it and holds only what is specific to that page.

Building a page

  1. Copy templates/page-template.html; replace the placeholders; one page stylesheet, one page script.
  2. Write the stylesheet with var(--…) names from this page. Need a colour that is not here? Add it to tokens.css with a comment, or declare it once in the page's :root block.
  3. Run npm run lint:css and npm test. Register the files in ACTIVE_FILES.md. A staff page that should be restricted gets a Staff_Page_Access row.
  4. Give the page the colour family of the person or department it belongs to, and the matching family class on its staff-dashboard tile.

Decisions log

This page is a working document. Every standard that changed how a page looks is recorded here, newest first, with the release that shipped it.

  • 2026-09-07 · the tail, and the dead sheets. The twelve sheets no family covered (the admin pages, production shifts, the price audit report, the employee bundles, the calibration tool, the vendor portals, the DTF prototype) read the token file, pixel-identical. Eighteen stylesheets that no page, script, route or import referenced (about 17,000 lines, several pre-dating the 2026 storefront) were deleted on Erik's instruction, with the two test fixtures that pointed at one of them. Every served stylesheet is now under stylelint and every served page that loads one loads the tokens. Next: the storefront and catalog palette pass — first an app-wide, zero-visual collapse of the page variables that share a value across many sheets into ramp tokens, then the customer-facing pages themselves, with Erik's authority to make them look better.
  • 2026-09-07 · quote builders (the last family). The four quote builders, the monogram form and the fast quote, and the thirteen calculator, dashboard and storefront pages that share their sheets read the token file, and so do the AE dashboard's nav and submit-form sheets (the last of shared_components/css): 2,573 colour uses became 1,415 exact tokens, 691 near tokens and 467 sheet-scoped variables; the shell's --pnw-* forest palette and the common sheet's --builder-* palette now alias the tokens wherever the values match. The generated hash-named quote-builder-inline.css is retired: the same 127 declaration sets live in quote-builder-utilities.css under names that say what they do (.qb-mt-4, .qb-bg-amber-100-p-2-8-r-4-c-amber-800). Their !important stays for now — it reproduces the precedence an inline attribute had over the builders' id-based rules, and dropping it means refactoring those id rules on the money path, which is design work, not a script. Follow-up: retire the flags builder by builder as the id rules are refactored; quote-print.css (296 flags over inline-styled print markup) is the biggest. The sticker pricing page keeps its own 20/24/32 spacing steps, which shadow the token scale on that page.
  • 2026-09-07 · staff pages + customer portal. The forty-five remaining pages under pages/ (art request and mockup detail, quote view, invoices, policies, the customer portal and login, the garment designer, the SanMar vendor portal) and the product page's shared sheet read the token file: 3,324 colour uses became 1,650 exact tokens, 1,023 near tokens and 651 sheet-scoped variables. Six sheets keep their own radius or shadow values that shadow the tokens on their pages (3-day tees, custom tees and caps, quote view, quote audit, the product page, the JDS mockup creator) — recorded, not moved. The icon font (Font Awesome) is exempt from the generic-font-family rule: its glyphs are private-use codepoints and no fallback renders them. Follow-up: seven sheets (invoice, quote view, quote audit, art request detail, policy detail, garment designer, embroidery contract pricing) are override stacks held together by !important (298 flags across the batch, all documented).
  • 2026-09-07 · calculators. The 25 calculator pages read the token file; every colour is a token or a sheet-scoped variable. The DTF, screen-print and universal pricing pages are stacks of fix/override sheets held together by !important (446 flags, all documented); untangling them is per-page design work, not a script — listed here as follow-up. The two sheets the quote builders also load wait for that family.
  • 2026-09-07 · dashboards. Sixty dashboards and the queue-dashboard system they share now read the token file; the person/department colours those pages already wore are code (--art-theme: var(--color-ruth)).
